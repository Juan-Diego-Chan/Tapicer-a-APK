# Hoja de ruta — App de gestión para tapicería

**Spec:** `docs/superpowers/specs/2026-11-04-app-tapiceria-design.md`

El spec es grande y sus módulos dependen unos de otros, así que se construye en **5 planes**. Cada uno deja una app que compila, se instala y sirve para algo. El detalle de cada plan se escribe al terminar el anterior, con el código real a la vista.

| # | Plan | Entrega | Secciones del spec | Estado |
|---|------|---------|--------------------|--------|
| 1 | **Fundamentos** (`2026-11-04-01-fundamentos.md`) | Proyecto Flutter + Firebase, inicio de sesión, roles Dueño/Empleado, alta y baja de usuarios, sueldos, reglas base con pruebas, CI | 4, 5, 7 | ✅ Completado |
| 2 | **Inventario** | Materiales, rollos, compras, carga inicial, ajustes, movimientos, costo promedio, lista de compras | 6.4, 6.5 | ✅ Completado |
| 3 | **Pedidos y muebles** | Clientes, pedidos con varios muebles, historial de precios, plantillas BOM, materiales usados, días trabajados, disponibilidad | 6.1, 6.2, 6.3, 6.6 | ✅ Completado |
| 4 | **Dinero** | Pagos, devoluciones, saldo, entregas de dinero al dueño con confirmación | 6.7, 6.7.1 | ✅ Completado |
| 5 | **Contabilidad y entrega** | Resúmenes semanal/mensual, márgenes, diferencias de material, APK firmado para instalar | 6.8, 9 | ✅ Completado |

## Estructura del repositorio (fija para todos los planes)

```
app/                      Proyecto Flutter (paquete Dart: tapiceria)
  lib/
    main.dart             Arranque: Firebase, persistencia sin conexión, ProviderScope
    app.dart              MaterialApp.router, tema, locale es_MX
    nucleo/               Utilidades compartidas: router, formatos de dinero/fecha, errores
    dominio/              Dart puro, sin Flutter ni Firebase: modelos y cálculos (testeables)
    datos/                Repositorios Firestore (un archivo por colección)
    funciones/<modulo>/   Pantallas y providers por módulo (auth, usuarios, inventario, pedidos, dinero, contabilidad)
  test/                   Mismo árbol que lib/
firebase/
  firestore.rules
  firestore.indexes.json
  pruebas_reglas/         Pruebas de reglas (Node + @firebase/rules-unit-testing + vitest)
firebase.json             Config de emuladores y reglas (raíz del repo)
.github/workflows/ci.yml
```

## Modelo de datos de Firestore (fijo; cada plan implementa su parte)

Regla del spec §5: lo sensible vive en colecciones que el empleado no puede leer. Las colecciones marcadas con 🔒 son **solo para el dueño**.

| Colección | Campos | Plan |
|---|---|---|
| `usuarios/{uid}` | `nombre`, `email`, `rol` (`'dueno'`\|`'empleado'`), `activo` (bool), `creadoEn` | 1 |
| 🔒 `usuarios_privado/{uid}` | `sueldoSemanal` (num; el dueño no tiene) | 1 |
| 🔒 `config/general` | `diasLaborales` (int, por defecto 6) | 1 |
| `materiales/{id}` | `nombre`, `categoria`, `unidad`, `stockMinimo`, `existencia` (solo con `increment`), `usaRollos`, `marcadoAgotandose` | 2 |
| 🔒 `materiales_costos/{id}` | `cantidadComprada`, `costoTotalComprado` (increments; promedio = cociente) | 2 |
| `rollos/{id}` | `materialId`, `codigo` (ej. `"#12"`), `cantidadInicial`, `existencia`, `fechaCompra` | 2 |
| 🔒 `rollos_costos/{id}` | `costoPorUnidad` (num o null = desconocido) | 2 |
| 🔒 `compras/{id}` | `materialId`, `rolloId?`, `cantidad`, `precioTotal`, `fecha`, `tipo` (`'compra'`\|`'inicial'`) | 2 |
| `movimientos/{id}` | `tipo` (`'compra'`\|`'inicial'`\|`'consumo'`\|`'ajuste'`), `materialId`, `rolloId?`, `cantidad` (con signo), `pedidoId?`, `muebleId?`, `usuarioId`, `fecha` | 2 |
| `plantillas/{id}` | `tipoMueble`, `lineas: [{materialId, cantidad}]` | 3 |
| `clientes/{id}` | `nombre`, `telefono`, `direccion` | 3 |
| `pedidos/{id}` | `folio`, `clienteId`, `cliente{nombre,telefono,direccion}`, `entrega` (`'recoge'`\|`'domicilio'`), `envio`, `comentarios`, `fechaIngreso`, `fechaEstimada`, `fechaTerminado?`, `fechaEntregado?`, `estado`, `creadoPor`, `ultimoCambioId?`, `pagado`, `ultimoPagoId?` | 3 |
| `pedidos/{id}/muebles/{id}` | `tipoTrabajo` (`'fabricacion'`\|`'reparacion'`), `tipoMueble`, `plantillaId?`, `precio`, `comentarios`, `estado`, `ultimoCambioId?` | 3 |
| `pedidos/{id}/muebles/{id}/materiales/{id}` | `materialId`, `rolloId?`, `cantidad`, `delCliente`, `usuarioId`, `fecha` | 3 |
| `pedidos/{id}/muebles/{id}/dias/{id}` | `usuarioId`, `dias` (múltiplo de 0.5), `fecha` | 3 |
| 🔒 lectura `pedidos/{id}/cambios_precio/{id}` | `campo` (`'precio'`\|`'envio'`\|`'alta'`\|`'cancelacion'`), `muebleId?`, `anterior`, `nuevo`, `motivo?`, `usuarioId`, `fecha` | 3 |
| `pagos/{id}` | `pedidoId`, `monto` (negativo = devolución), `forma` (`'efectivo'`\|`'transferencia'`), `recibidoPor`, `fecha` | 4 |
| `entregas/{id}` | `empleadoId`, `monto`, `forma`, `fecha`, `estado` (`'pendiente'`\|`'confirmada'`\|`'rechazada'`), `revisadoEn?` | 4 |
| 🔒 `pagos_sueldo/{id}` | `usuarioId`, `monto`, `fecha` | 4 |
| `cajas/{uid}` | `enMano`, `ultimoPagoId?`, `ultimaEntregaId?` | 4 |

Regla de grupo (Plan 5): las reglas permiten leer `cambios_precio` como grupo de colecciones (`match /{ruta=**}/cambios_precio/{c}`, solo dueño, solo lectura) para que Contabilidad liste los cambios del periodo; las escrituras siguen regidas por la regla anidada de cada pedido.

Fechas: `Timestamp` de Firestore. Dinero: pesos como `num` con 2 decimales, redondeado en `dominio/`.
